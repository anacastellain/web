O Protocolo HTTP (HyperText Transfer Protocol)

O HTTP é o protocolo fundamental da World Wide Web. Ele define como as mensagens são formatadas e transmitidas, permitindo a comunicação padronizada entre os sistemas da web.

1. O Papel do HTTP na Comunicação

O papel principal do HTTP é servir como a "linguagem comum" que viabiliza a troca de dados entre navegadores (que atuam na ponta do usuário) e servidores web (onde os sites e recursos estão hospedados). Sem ele, os computadores não saberiam interpretar as solicitações de páginas.

2. Cliente, Servidor, Requisição e Resposta

  • Cliente: É o aplicativo ou dispositivo do usuário (como o Google Chrome, Firefox ou um script) que inicia a comunicação solicitando um recurso.
  • Servidor: É o computador de alta capacidade que armazena os arquivos do site e aguarda as chamadas dos clientes para atendê-las.
  • Requisição (Request): É a mensagem enviada pelo cliente ao servidor pedindo uma informação ou ação.
  • Resposta (Response): É a mensagem enviada de volta pelo servidor ao cliente, contendo o status da solicitação e os dados solicitados (como o código HTML de uma página).

3. Principais Métodos HTTP (GET e POST)

  • GET: Utilizado para solicitar a recuperação de um recurso ou página do servidor (os dados vão visíveis na URL).
  • POST: Utilizado para enviar dados novos ao servidor (como o preenchimento de um formulário de cadastro ou contato), mantendo o corpo da mensagem oculto na URL.

4. Exemplo de uma Requisição HTTP

Abaixo temos um exemplo clássico de requisição de texto enviada por um cliente:

GET /index.html HTTP/1.1
Host: www.exemplo.com.br
User-Agent: Mozilla/5.0
Accept: text/html

5. Exemplo de uma Resposta HTTP

Abaixo temos o exemplo correspondente da resposta enviada pelo servidor:

HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 1383

<!DOCTYPE html>
<html>
<head><title>Página Exemplo</title></head>
<body><h1>Olá, Mundo!</h1></body>
</html>

6. Códigos de Status HTTP

Os códigos de status informam o resultado da requisição feita pelo cliente. Abaixo estão os principais:

  • 200 OK: A requisição foi bem-sucedida e o servidor retornou o recurso solicitado.
  • 301 Moved Permanently: O recurso foi movido permanentemente para uma nova URL (redirecionamento).
  • 400 Bad Request: A requisição está mal formatada ou contém sintaxe inválida que o servidor não conseguiu processar.
  • 403 Forbidden: O servidor entendeu o pedido, mas se recusa a autorizá-lo (falta de permissão de acesso).
  • 404 Not Found: O recurso solicitado não foi encontrado no servidor (página inexistente).
  • 500 Internal Server Error: Erro genérico no servidor, indicando que ocorreu uma falha inesperada no processamento interno.
